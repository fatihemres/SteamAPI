## 1. Release Overview

**SteamAPI v0.2.0** represents a comprehensive modernization of the application, transitioning from an unmaintained .NET 6 prototype using obsolete synchronous networking primitives to a modernized **.NET 10** service with asynchronous networking, formal request validation, standardized error handling, and resource limits.

Key milestones accomplished across the modernization lifecycle:
- **Phase 2A:** Complete .NET 10 target framework and CI pipeline migration.
- **Phase 2B:** Replacement of synchronous `WebClient` with asynchronous, pooled `HttpClient` architecture.
- **Phase 2C:** Formalization of request validation and RFC 9457 Problem Details error handling.
- **Phase 3A:** Comprehensive technical audit; the NuGet vulnerability check (`dotnet list package --vulnerable`) reported no known package vulnerabilities at the time of the audit.
- **Phase 3B:** Controlled live smoke verification against Steam's suggestion endpoint.
- **Phase 3C:** Test-driven release risk remediation, resource hardening, and professional documentation.
- **Phase 3D:** Final controlled live Steam integration smoke verification and request accounting audit.
- **Phase 3E:** Final documentation harmonization, PR metadata alignment, and release-readiness review.

## 2. Detailed Changes

### 2.1. Framework Modernization
- **Runtime & Target Framework:** Migrated all projects (`Core.csproj`, `SteamAPI.csproj`, `SteamAPI.Tests.csproj`) from `net6.0` to `net10.0`.
- **CI Modernization:** Updated the cross-platform GitHub Actions workflow (`.github/workflows/ci.yml`) to use the official .NET 10 SDK (`dotnet-version: '10.0.x'`).

### 2.2. HTTP Infrastructure Modernization
- **Async Pipeline:** Replaced obsolete synchronous `WebClient` and global `ServicePointManager` with an asynchronous `HttpClient` registered as a typed client (`SteamService`) via dependency injection.
- **Connection Management:** Delegated socket management and DNS rotation to `IHttpClientFactory`.
- **Cancellation Propagation:** Full `CancellationToken` flow across controller, service, and HTTP client methods.
- **Controlled Upstream Timeout:** Configured a strict 30-second `HttpClient.Timeout` with full response-body coverage via `HttpCompletionOption.ResponseContentRead`.
- **URL Parameter Encoding:** Implemented robust RFC 3986 percent-encoding (`Uri.EscapeDataString`) for all user-supplied search terms.

### 2.3. API Reliability and Security Hardening
- **Input Length Capping:** Enforced a maximum search term boundary of **200 UTF-16 code units** (`string.Length`) via `[MaxLength(200)]` on `GetSteamGameInfoRequestModel.Game` and defensive controller checks. Oversized inputs are rejected with HTTP 400 Bad Request.
- **Typed Upstream Parsing Exception:** Introduced `SteamResponseParseException` for cases where Steam suggestion markup contains recognized `match` elements that fail validation. Mapped cleanly to **HTTP 502 Bad Gateway** with sanitized ProblemDetails, preventing internal server error (500) crashes.
- **Redirect Hardening:** Configured `SocketsHttpHandler` with `AllowAutoRedirect = false` to prevent unexpected cross-host redirect following.
- **Response Size Bounding:** Configured `MaxResponseContentBufferSize = 1,048,576` (1 MiB) to protect against memory exhaustion from oversized upstream payloads.
- **Standardized RFC 9457 Contracts:** Unified error payloads across validation failures (`400 Bad Request`), upstream failures (`502 Bad Gateway`), and timeouts (`504 Gateway Timeout`).

## 3. Compatibility and Migration Notes

> **Breaking Changes Notice**  
> While successful `POST /steam` responses remain structurally identical, several breaking changes have been introduced for invalid or failing requests:

1. **Runtime Requirement (.NET 10):**
   - Hosting environments must have the .NET 10.0 Runtime installed.
2. **Search Input Length Limit (200 UTF-16 Code Units):**
   - In v0.1.1, search terms of unbounded length were accepted.
   - In v0.2.0, requests with `game.Length > 200` are rejected with `HTTP 400 Bad Request`.
3. **Structured RFC 9457 Error Payloads:**
   - Error responses now return `ProblemDetails` and `ValidationProblemDetails` JSON payloads. Clients parsing legacy error strings or status codes must be updated.
4. **Upstream Error Status Codes:**
   - Identifiable, handled upstream Steam failures (such as non-success HTTP status codes, network connectivity faults, refused redirects, payload overflow, and unrecognized `match` markup) are now mapped to `HTTP 502 Bad Gateway` (previously causing unhandled 500 exceptions or empty collections).
   - Upstream timeouts now return `HTTP 504 Gateway Timeout`.
5. **Listing JSON Structure (Preserved):**
   - Successful responses continue returning a top-level array of Listing objects with the exact six camelCase fields: `name`, `storeLink`, `imageLink`, `price`, `saleType`, `appId`.

## 5. Known Limitations

1. **HTML Scraping Fragility:** The application relies on parsing HTML from Steam's web search suggestion endpoint. A major DOM overhaul by Valve that removes the `.match` CSS class would cause the endpoint to return `[]` (empty results) rather than an error.
2. **Missing Currency Metadata:** The `price` property is numeric only; it carries no currency code. In regions such as Turkey, prices may be denominated in USD rather than local currency.
3. **Compiler Warnings:** Four pre-existing `CS8618` nullability warnings remain unresolved in `CultureValue.cs` and `GetSteamGameInfoRequestModel.cs` and are outside the scope of this release.
4. **No Application-Level Rate Limiting:** The service does not implement in-memory request throttling or outbound request rate limiting against Steam. Deployments should sit behind a managed reverse proxy or API gateway configured with rate limiting to prevent upstream IP bans.
5. **No Production Monitoring:** Application-level distributed tracing, health checks, and OpenTelemetry or Prometheus metrics are not configured in this milestone.
